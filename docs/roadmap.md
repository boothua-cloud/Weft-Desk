# 路线图与待办清单

定位：一个能管住 tailnet 的桌面客户端，不是 headscale 的 Web 后台克隆。

判断一件事值不值得做，看三条：

1. 能不能替代一次命令行操作；
2. 能不能回答一个「为什么不行 / 为什么慢」；
3. 是不是只依赖已有接口和已有的 TUN，不新增基础设施。

三条中两条成立就进 P0/P1，一条都不到就进 P2 或不做。

成本标注：小 = 一天内，中 = 两三天，大 = 一周以上或要动网络层。带 ★ 的是第二轮补充的。

## 优先级总览

| 阶段 | 现在最该做的 |
|---|---|
| P0 | 连通性诊断 · 服务端自签证书 · ACL 补 `autoApprovers` 与 `hosts` · 策略历史回滚 |
| P1 | 设备巡检清单 · ACL 风险体检 · 内嵌终端 · 审计页面化 · ⌘K 命令面板 |
| P2 | 出口节点 · 分流 · 本地名字解析 · MTU 探测 · 文件互传 · 公证与签名 |

## 两条来自代码的真缺口

- **服务端自签证书没开关**。`sharedHTTP` 用的是默认 Transport，headscale 用 https 加自签证书时，API 直接报 `x509: certificate signed by unknown authority`，界面上无处可改。而 `AllowInsecure` 那个勾选项是给「内网应用自签证书」用的（`model.go` 注释写得很清楚），跟服务端无关。内网自建 headscale 十有八九是自签，这个坑迟早碰到。
- **代理只认环境变量**。HTTP 客户端没设 Transport，所以 `HTTPS_PROXY` 生效，但 macOS「系统设置 → 网络 → 代理」里配的不生效——GUI 应用拿不到那份配置。企业网络里访问外部 headscale 时会卡在这里。

## 一、策略与权限

- [ ] **表单补 `hosts`**（小）— 别名写一次，规则里用名字代替 IP。现在归到 `extra` 原样保留，只能去源码改。
- [ ] **表单补 `autoApprovers`**（小）— 按标签自动批准子网路由和出口节点。跟现有「批准路由」是一件事的两端。
- [ ] **表单补 `ssh`**（中）— Tailscale SSH 的规则段。跟内嵌终端一起做才有意义。
- [ ] **策略历史快照**（中）— 每次保存前把旧策略存本地，带 diff 和一键回滚。headscale 不存历史，这是客户端独有的价值。
- [ ] **保存前 diff 预览**（小）— 点保存先弹「将新增 1 条、删除 2 条」，确认再写，防止静默覆盖别人刚改的内容。
- [ ] ★ **ACL 风险体检**（中）— 跟现有校验互补：校验管语法和引用对不对，体检管「这条等于没设防」。比如目标写 `*:*`、src 用 `*`、22/3306/6379/9200 对全员开放。每条给出后果说明，不直接下架。
- [ ] ★ **变更推送到 IM**（中）— 保存成功后往企微/飞书/Slack 的 webhook 发一条「谁在什么时候改了哪几条」。小团队最容易出的事就是两个人同时改策略。
- [ ] **策略模板库**（中）— 现在只有三个起点。补「K8s 集群」「家庭」「外包隔离」「只读审计员」，并支持把当前策略另存为模板。
- [ ] **校验提示加一键修**（中）— 现在提示「会补成 `group:Boothua`」，得自己去改。给一个按钮批量套用。
- [ ] ★ **待审模式**（中，可选）— 改完不直接写服务端，导出一份待审 JSON 加 diff 说明，同事 review 后再应用。

## 二、设备与人员

- [ ] **设备迁移到其他成员**（小）— `/node/{id}/user` 没接。多成员网络调整归属只能上命令行。
- [ ] **密钥到期日期选择**（小）— 现在只有「永不过期」和「立刻过期」两个极端。
- [ ] ★ **过期设备一键续 30 天**（小）— 比填日期更常用，一个按钮解决。
- [ ] **批量操作**（中）— 多选设备批量打标签、批路由、批过期、批删除。
- [ ] **按标签折叠分组**（中）— server 一组、手机一组，现在是一条平表。
- [ ] **设备巡检清单**（中，P1）— 把「需要你处理」的挑出来：通告了但没批准的路由、7 天内过期的密钥、离线超过 7 天的设备、从未使用过的授权 Key。数据都在 `advertisedRoutes` / `approvedRoutes` / `expiry` 里，不用新接口。
- [ ] **邀请流程**（中）— 建 Key 后顺手生成一段接入说明（服务端地址 + 安装命令 + Key），发到 IM 就能拉人。
- [ ] **授权 Key 加备注**（小）— headscale 不记这把 Key 给了谁，本地存一行备注。
- [ ] ★ **成员统计视图**（小）— 每个成员几台设备、几台在线、最后活跃时间。管理视角，比一张全员设备表好用。
- [ ] ★ **设备名批量规范化**（中）— 按 `角色-序号` 之类规则批量改名，先预览再执行。设备一多，命名会烂掉。

## 三、网络能力

- [ ] **连通性诊断**（中，P0）— 选两台设备测握手和 ping，显示直连还是 DERP、走的哪个 relay、延迟多少。唯一能解释「为什么慢」的功能。
- [ ] ★ **MTU 探测**（中）— 「能 ping 通但网页打不开」是 TUN 的经典疑难，多半是 MTU 设大了。给一个从 1500 往下探的工具，直接给出建议值。
- [ ] ★ **延迟与丢包曲线**（中）— 对关键设备持续探测，画 24 小时曲线。「晚上八点就卡」这种事，只有曲线能证明。
- [ ] **内嵌终端**（中，P1）— 走 100.x 加 `x/crypto/ssh`，配合 ACL 的 `ssh` 规则。
- [ ] **出口节点**（大）— 文档里写着「不做」，但这是很多人用 Tailscale 的主要理由。headscale 侧支持，客户端侧是改路由表。
- [ ] **分流（split tunneling）**（大）— 只接管指定网段，其余走本地网络。「同时连公司 tailnet 和家里 NAS」现在做不到。
- [ ] **本地名字解析**（中）— `127.0.0.1:53` 起个转发器，把设备名解析成 100.x；或者同步 hosts。不依赖 headscale 任何配置。
- [ ] **文件互传**（中）— Taildrop 做不了（要对端也是 tailscaled），但在 100.x 上临时起个 TCP 服务直接发更简单。
- [ ] ★ **DERP 使用占比**（小）— 当前走哪个 relay、多少流量走 relay。跟延迟曲线配着看，能判断该不该自建 DERP。
- [ ] **服务发现扫描**（中，P2）— 扫 tailnet 内 22/80/443/3306，列出哪台在跑什么。主动探测要有明确开关，不能默认开。

## 四、应用与转发

- [ ] **应用图标自动抓 favicon**（小）— 现在卡片是首字母，抓一次落到本地缓存更像「应用」。
- [ ] **应用打开时自动起转发**（小）— 有些内网服务只认固定端口。
- [ ] **`weft://` 链接**（小）— `weft://open?host=web-01&port=8080`，IM 里点一下直接开窗口。
- [ ] **转发预设组**（小）— 常用 22 / 3306 / 6379 一键成组。
- [ ] ★ **端口占用预检**（小）— 转发和应用代理的端口被别的进程占了时提前报，现在要等启动失败。
- [ ] ★ **转发限速**（中）— 单条转发限制带宽，防止一条 rsync 把整条链路吃满。
- [ ] **临时分享地址**（中）— 把某个 100.x 服务包成一次性带 token 的本地地址，发给同 tailnet 的人。
- [ ] ★ **卡片拖动排序**（小）— 应用和转发都支持拖，现在只能按创建顺序。

## 五、可观性与排障

- [ ] **每台设备的速率与握手时间**（中）— 现在只有在线/离线。加 rx/tx 和最后一次握手。
- [ ] **审计页面化**（中，P1）— 已有 `AuditEvent`，但只记六类操作（保存配置、切换服务端、删除服务端、更新凭证、测试连接、自动续期），界面只显示最近 7 条。补全写操作、支持搜索和导出。
- [ ] **一键诊断包**（中）— 日志 + 脱敏配置 + 网络状态打成 zip。现在只能让用户跑 `--diag` 再自己找文件。
- [ ] **托盘提醒**（小）— 设备上下线、密钥将过期、巡检失败才弹一次；图标带待处理数量。
- [ ] ★ **离线态**（中）— headscale 连不上时，页面显示上次缓存的数据并标上「3 分钟前」，而不是空白或报错。现在一断网整个管理区就废了。

## 六、客户端体验

- [ ] **轮询自适应**（中）— 现在 3 秒全量拉 peers。窗口不可见降频、失败退避、能增量就增量。
- [ ] ★ **⌘K 命令面板**（中，P1）— 一个输入框搜设备、应用、页面、动作（「批准 web-01 的路由」）。功能一多，没有这个就只能靠记位置。
- [ ] ★ **首次启动向导**（中）— 地址 → Key → 连接 → 建第一个应用，四步走完能上网。现在填配置页信息密度高，新用户容易迷路。
- [ ] **只读模式开关**（小）— 给「只想看一眼」的场景，省得手滑保存。
- [ ] **全局快捷键唤起**（小）— 默认 `⌘⇧W` / `Ctrl+Shift+W`。
- [ ] **菜单栏小面板**（中）— 显示在线设备数、当前出口、快捷应用。
- [ ] ★ **应用小窗钉在最前**（中）— 把某个应用拉成小窗置顶，适合盯监控面板。
- [ ] ★ **最近使用与收藏**（小）— 应用和转发都记「上次用的」，置顶显示。
- [ ] **中英双语**（中）— 现在全中文。要一次做干净，别留半截。

## 七、工程与发布

- [ ] **服务端自签证书**（小，P0）— 按服务端保存「信任的 CA 或指纹」，替代全局跳过校验；顺手把 `AllowInsecure` 的文案改清楚，现在容易被当成服务端选项。
- [ ] ★ **读取系统代理设置**（中）— macOS 走 `scutil --proxy`，Windows 走注册表，别只认 `HTTPS_PROXY`。
- [ ] **macOS 公证 + Windows 代码签名**（中）— 别人下载要绕 Gatekeeper、弹 SmartScreen，这比多两个功能更决定别人愿不愿意装。
- [ ] **CLI 伴侣**（中）— `weft status` / `weft forward add` / `weft acl diff`。
- [ ] **配置自动备份与换机迁移**（中）— 服务端列表、应用、转发规则、策略快照打成一个包，密钥除外。
- [ ] **自动更新增量下载**（中）— 先确认现在是不是整包下载。

## 明确不做

- **数据库客户端、K8s 面板、Web 控制台** — 做下去就是另一个产品，跟「管住 tailnet」的定位打架。
- **多 tailnet 并行连接** — 单 TUN 撑不住。切换服务端时断开重连是更诚实的做法。
- **Taildrop 原生兼容** — 要对端也是 tailscaled，投入产出比不如自建一套文件互传。
- **兼容 Tailscale 官方 API** — 只承诺 headscale。

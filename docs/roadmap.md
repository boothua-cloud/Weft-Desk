# 路线图与待办清单

定位：一个能管住 tailnet 的桌面客户端，不是 headscale 的 Web 后台克隆。

判断一件事值不值得做，看三条：

1. 能不能替代一次命令行操作；
2. 能不能回答一个「为什么不行 / 为什么慢」；
3. 是不是只依赖已有接口和已有的 TUN，不新增基础设施。

三条中两条成立就进 P0/P1，一条都不到就进 P2 或不做。

成本标注：小 = 一天内，中 = 两三天，大 = 一周以上或要动网络层。

## 优先级总览

| 阶段 | 现在最该做的三件 |
|---|---|
| P0 | 连通性诊断 · ACL 补 `autoApprovers` 与 `hosts` · 策略历史回滚 |
| P1 | 设备巡检清单 · 内嵌终端 · 审计页面化 · 策略模板库 |
| P2 | 出口节点 · 分流 · 本地名字解析 · 文件互传 · 公证与签名 |

---

## 一、策略与权限

- [ ] **表单补 `hosts`**（小）— 别名写一次，规则里用名字代替 IP。现在归到 `extra` 原样保留，只能去源码改。
- [ ] **表单补 `autoApprovers`**（小）— 按标签自动批准子网路由和出口节点。跟现有「批准路由」是一件事的两端，省掉每次新加子网手点一次。
- [ ] **表单补 `ssh`**（中）— Tailscale SSH 的规则段。跟内嵌终端一起做才有意义。
- [ ] **策略历史快照**（中）— 每次保存前把旧策略存本地，带 diff 和一键回滚。headscale 不存历史，这是客户端独有的价值：出事能回答「昨天谁把这条删了」。
- [ ] **保存前 diff 预览**（小）— 点保存先弹「将新增 1 条、删除 2 条、改 1 条」，确认再写。防止静默覆盖别人刚改的内容。
- [ ] **策略模板库**（中）— 现在只有三个起点。补「K8s 集群」「家庭」「外包隔离」「只读审计员」，并支持把当前策略另存为模板。
- [ ] **校验提示加一键修**（中）— 现在提示「会补成 `group:Boothua`」，得自己去改。给一个「按提示修好」按钮批量套用。
- [ ] **写操作二次确认**（小，可选）— 保存策略、删成员这类不可逆操作，弹 diff 或要求输入名字。

## 二、设备与人员

- [ ] **设备迁移到其他成员**（小）— `/node/{id}/user` 没接。多成员网络调整归属现在只能上命令行。
- [ ] **密钥到期日期选择**（小）— 现在只有「永不过期」和「立刻过期」两个极端，中间填不了日期。
- [ ] **批量操作**（中）— 多选设备批量打标签、批路由、批过期、批删除。设备一多，一个个点不可用。
- [ ] **按标签折叠分组**（中）— server 一组、手机一组，现在是一条平表。
- [ ] **设备巡检清单**（中，P1）— 把「需要你处理」的挑出来：通告了但没批准的路由、7 天内过期的密钥、离线超过 7 天的设备、从未上线的授权 Key。数据都在 `advertisedRoutes` / `approvedRoutes` / `expiry` 里，不用新接口。
- [ ] **邀请流程**（中）— 建 Key 之后顺手生成一段可复制的接入说明（服务端地址 + 安装命令 + Key），发到 IM 就能拉人。现在建完 Key 还得自己解释怎么装。
- [ ] **授权 Key 加备注**（小）— headscale 不记这把 Key 给了谁，客户端本地存一行备注和使用时间。

## 三、网络能力

- [ ] **连通性诊断**（中，P0）— 选两台设备测握手和 ping，显示直连还是 DERP、走的哪个 relay、延迟多少。现在卡了只能翻日志，这是唯一能解释「为什么慢」的功能。
- [ ] **内嵌终端**（中，P1）— 走 100.x 加 `x/crypto/ssh`，配合 ACL 的 `ssh` 规则。有了网卡，下一步就是连上去。
- [ ] **出口节点**（大）— 文档里写着「不做」，但这是很多人用 Tailscale 的主要理由。headscale 侧支持，客户端侧是改路由表，跟现有 TUN 同层。
- [ ] **分流（split tunneling）**（大）— 只接管指定网段，其余走本地网络。现在要么全接管要么不接管，「同时连公司 tailnet 和家里 NAS」做不到。
- [ ] **本地名字解析**（中）— 127.0.0.1:53 起个转发器，把设备名解析成 100.x；或者同步 hosts。文档说「统一用 IP」，但敲名字比敲 IP 顺手得多。
- [ ] **文件互传**（中）— Taildrop 做不了（要对端也是 tailscaled），但可以在 100.x 上临时起个 TCP 服务直接发。实现比 Taildrop 简单。
- [ ] **服务发现扫描**（中，P2）— 扫 tailnet 内 22/80/443/3306，列出哪台机器在跑什么。主动探测要有明确开关和提示，不能默认开。

## 四、应用与转发

- [ ] **应用图标自动抓 favicon**（小）— 现在卡片是首字母，抓一次 favicon 落到本地缓存更像「应用」。
- [ ] **应用打开时自动起转发**（小）— 有些内网服务只认固定端口，应用一开就把对应转发拉起来。
- [ ] **`weft://` 链接**（小）— `weft://open?host=web-01&port=8080`，IM 里点一下直接开应用窗口。
- [ ] **转发预设组**（小）— 常用 22 / 3306 / 6379 一键成组，现在一条条敲。
- [ ] **临时分享地址**（中）— 把某个 100.x 服务包成一次性带 token 的本地地址，发给同 tailnet 的人。

## 五、可观性与排障

- [ ] **每台设备的速率与握手时间**（中）— 现在只有在线/离线。加 rx/tx 和最后一次握手，能看出谁在真跑流量。
- [ ] **审计页面化**（中，P1）— 已有 `AuditEvent`，但只记「保存配置 / 切换服务端 / 删除服务端 / 更新凭证 / 测试连接 / 自动续期」六类，界面上只显示最近 7 条。补全写操作、支持搜索和导出。
- [ ] **一键诊断包**（中）— 日志 + 脱敏配置 + 网络状态打成一个 zip。现在只能让用户跑 `--diag` 再自己找文件。
- [ ] **托盘提醒**（小）— 设备上下线、密钥将过期、巡检失败才弹一次；托盘图标带待处理数量。

## 六、客户端体验

- [ ] **轮询自适应**（中）— 现在 3 秒全量拉 peers。窗口不可见降频、请求失败退避、能增量就增量。设备上百台后 headscale 会疼。
- [ ] **只读模式开关**（小）— 给「只想看一眼」的场景，工具栏一个开关，省得手滑保存。
- [ ] **全局快捷键唤起**（小）— 默认 `⌘⇧W` / `Ctrl+Shift+W`。
- [ ] **菜单栏小面板**（中）— macOS 菜单栏点开显示在线设备数、当前出口、快捷应用。
- [ ] **中英双语**（中）— 现在全中文。工程上不难，但要一次做干净，别留半截。

## 七、工程与发布

- [ ] **macOS 公证 + Windows 代码签名**（中）— 现在别人下载要绕 Gatekeeper、弹 SmartScreen。这比多两个功能更决定别人愿不愿意装。
- [ ] **CLI 伴侣**（中）— `weft status` / `weft forward add` / `weft acl diff`，让脚本能用。
- [ ] **自动更新增量下载**（中）— 确认一下现在是不是整包下载。
- [ ] **策略与配置的导入导出**（小）— 不含密钥的配置包，团队统一。

---

## 明确不做

- **数据库客户端、K8s 面板、Web 控制台** — 做下去就是另一个产品，跟「管住 tailnet」的定位打架。
- **多 tailnet 并行连接** — 单 TUN 撑不住。切换服务端时断开重连是更诚实的做法。
- **Taildrop 原生兼容** — 要对端也是 tailscaled，投入产出比不如自建一套文件互传。
- **兼容 Tailscale 官方 API** — 只承诺 headscale。

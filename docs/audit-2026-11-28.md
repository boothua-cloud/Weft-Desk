# 代码审计 · 2026-11-28

范围：当前 `main`（0.1.5 + 未发布的界面/路由改动），Go 后端约 1.19 万行，前端约 0.93 万行。
方法：人工通读关键路径 + `go vet` / `govulncheck` / `npm audit` / `go test` / `go test -race`。

先说结论：**没有发现可被远程直接利用的漏洞，也没有 SQL 注入、命令注入、XSS 这类硬伤**。
问题集中在三处：应用内浏览器把第三方页面放进了有绑定能力的 WebView、Windows 提权自启的落地位置、
以及一些「配置能走到不该走的地方」的边界校验缺失。

---

## P1 需要处理

### 1. 应用内窗口加载第三方页面，页面能调所有后端方法

`weft.go:1608` 用 `app.Window.NewWithOptions` 开一个普通 WebView 窗口，700ms 后
`win.SetURL(内网地址)`。这个窗口和主界面一样，享受 Wails 的全套绑定。

Wails v3.0.0 收到 `wails:` 开头的消息时只判断「是不是主 frame」
（`pkg/application/application.go:865`），**不看来源 origin**，就直接分发给绑定处理器。
也就是说：这个窗口里显示的任何内网应用页面（包括它自己被 XSS 打穿的页面），只要拼一条
`wails:` 消息，就能调用 `RevealCredential("main")` 拿到 Headscale 管理 API Key、
调 `SaveConfig` / `DeleteDevice` / `ApproveRoutes`，然后往外发。

这是设计层面的问题，不是某一行写错：
- 应用内窗口是「给别人看的第三方内容」和「有全部管理权限的宿主」混在同一个上下文里；
- 当前 Wails 版本没有按窗口开关绑定的选项（`WebviewWindowOptions` 里只有 KeyBindings）。

可选的处理方式，按代价从低到高：
1. 书签默认「用系统浏览器打开」，应用内窗口改成显式勾选；
2. 应用内窗口只允许打开白名单域名；
3. 高危方法（`RevealCredential`、`SetCredential`、`SaveConfig`、`SaveProfileRaw`、删除类）
   二次校验调用来源窗，非主窗口一律拒绝；
4. 等 Wails 支持按窗口关闭绑定后升级。

只做 3 的话，绑定仍然能被非主窗口调用去改配置，只是拿不到明文凭证，建议 1 + 3 一起。

### 2. Windows 的提权自启指向用户可写目录

`helper_windows.go:94` 创建计划任务：`/SC ONLOGON /RL HIGHEST /TR "<当前 exe 路径>"`。
exe 装在 `%LOCALAPPDATA%\Programs\Weft` 时，任何以该用户身份运行的代码都能替换这个 exe，
下次登录就以最高权限执行 —— 本地提权 + 持久化。

macOS 那边是 `install -m 544 -o root -g wheel` 装到 `/Library/PrivilegedHelperTools`，
root 拥有、不可写，是对的；Windows 缺这一层。

建议：任务不要直接跑用户目录里的 exe，或至少校验 exe 的签名/哈希（存在 HKCU 的期望值里也能被改，
所以正解是把 helper 复制到 `%ProgramFiles%` 或 `%ProgramData%` 下由管理员拥有后再让任务指向它）。

### 3. 特权助手从 /tmp 安装（TOCTOU）

`systun_unix.go:457` 把自身二进制复制到 `/tmp/weft-elevate-bin-*`（0755），
`helper_darwin.go:98` 又把 plist 写到 `/tmp/weft-*.plist`，然后 root 执行
`install ... /tmp/...`。从「文件写进 /tmp」到「root 复制它」之间有窗口期，
同用户进程可以改这两个文件，随后被 root 采纳。

同用户的恶意代码本来也能自己弹一次授权框，所以实际门槛不高，但这属于必须消掉的经典模式：
- 先在用户目录生成内容，算好 SHA-256，脚本里校验后再 install；
- 或者把二进制放进一个 0700 的私有临时目录（`os.MkdirTemp`），而不是共享的 /tmp。

### 4. 更新链路没有完整性校验，Windows 会直接执行下载物

`update.go:497` 的 `downloadFile` 只比对字节数，没有校验和/签名。兜底路径（`CheckUpdate` 失败时）
从 GitHub API 取 `browser_download_url` 直接下载，然后 `openInstaller` 在 Windows 上是
`exec.Command(path).Start()` —— 下载完立刻执行。TLS 挡住了链路中间人，但仓库被拿走、
或 API 返回被篡改时没有任何第二道防线。

另外 `update.go:341`：`dst := filepath.Join(dir, asset.Name)` 没有取 `Base()`，
附件名里带 `../` 就能写到下载目录之外（macOS 会自动打开，Windows 会执行）。

建议：`filepath.Base`；发布里带上 `sha256`（GitHub release 的 digest 字段或 assets 旁的校验文件），
下载后比对再执行；Windows 至少改成「打开所在目录」，让用户自己点。

### 5. 证书配置会静默降级；BaseURL 允许明文 http

`controlplane.go:110`：

```go
case strings.TrimSpace(c.CACert) != "":
    if pool, err := certPool(c.CACert); err == nil {   // 解析失败就什么都不做
        tr.TLSClientConfig = &tls.Config{RootCAs: pool, ...}
    }
case c.ControlInsecure:
```

注释写的是「读不出来就报错，别静默退回系统 CA」，实际是解析失败 → 用系统 CA 继续连。
`SaveProfileRaw` 保存时会校验，但 `SaveConfig`（导入配置、旧配置迁移）不校验，
所以存在「用户以为钉死了 CA，其实没钉」的路径。建议解析失败就返回错误，不要吞。

`BaseURL` 没有 scheme 限制，填 `http://` 时管理 API Key 以 `Authorization: Bearer` 明文过网
（自建服务在局域网里很常见）。建议明文时在保存处和界面上明确警示，或要求勾一个「我接受明文传输」。

## P2 建议修

### 6. 端口转发 / SOCKS5 没有认证，可以开到 0.0.0.0

`forward.go:162`：`bindAny` 时监听所有接口，`forward.go:175` 的 SOCKS5 也没有用户名密码。
开关叫「对内网开放」，但对同网段的任何人来说，这就是一个用你的 tailnet 身份访问内网的免费代理。
建议：0.0.0.0 时至少要求确认（现在有确认框，但文案可以点明这一点），SOCKS5 在 0.0.0.0 下强制
要求用户名密码或直接禁用。

### 7. 书签地址没有 scheme 白名单

`OpenApp` → `SetURL(raw)`，`OpenInBrowser` → `open <url>` / `rundll32 ... <url>`。
`file://`、`-a Calculator` 这类值会被当成参数或本地文件处理。书签可能来自同步（见第 8 条），
所以不该完全信任。建议在 `ResolveURL` 里只放行 http/https，其余直接报错。

### 8. 同步：/v1/info 不鉴权；强制 http；对端 ID 直接入库

- `apps_sync.go:237`：`/v1/info` 不需要同步码，tailnet 内任何被 ACL 放行的设备都能读到
  主机名、版本、书签数量。建议一并纳入 `guardSync`，或只返回 `{"app":"云栈"}`。
- `apps_sync.go:422`：不管输入写的是不是 https，都拼成 `http://`。tailnet 内是 WireGuard 加密，
  问题不大，但「输入 https 却被降级」这件事本身应该避免。
- `apps_sync.go:490`：合并时对端书签的 `ID` 直接沿用（`SaveAppRaw` 是 `ON CONFLICT(id) DO UPDATE`）。
  两台设备的 ID 撞上时（升级、复制数据库、旧的 `a1` 这类固定 ID），会把本机另一条书签的 URL 覆盖掉。
  建议本机始终自己生成 ID，对端 ID 只用于展示。

### 9. 本地端点没有鉴权

- `appoverlay.go:31`：控制端点带 `Access-Control-Allow-Origin: *`，`GET /close?w=<id>` 不需要任何凭据。
  端口是随机的，影响也就是「网页能关掉你的应用窗口」，但没理由留着：加一个随机 token 传给注入脚本即可。
- `proxy.go:57`：本地反向代理监听 127.0.0.1 随机端口，同机任意进程都能借它访问 tailnet 内网
  （用的是你的节点身份，ACL 看到的是你）。WebView 带不了自定义头，所以更好的做法是给每个代理
  生成一段随机路径前缀（能力式 URL），代理只接受这个前缀下的请求。

### 10. 自动续期可能留下一把无主的管理 Key

`weft.go:848`：新建 Key 成功后写钥匙串失败会 `return`，新 Key 没有被吊销，
服务端就多了一把 90 天有效、本地无记录的凭证。失败分支里补一次 `ExpireAPIKey(fresh)` 即可。

另外自动续期固定 90 天、权限不降级，等于让客户端长期持有管理凭据；至少应在审计里可见（现在有），
可以考虑缩短到 30 天或改成「快到期时提醒用户手动换」。

## P3 顺手改

- `tunnel.go:83`：`ControlPlane` / `ProfileID` 直接拼进状态目录名，`..`、`/` 没有过滤
  （`SaveConfig` 接受前端传来的任意字符串）。建议白名单字符或改成哈希。
- `GetState`（`weft.go:957`）等处直接读 `s.engine`、`s.cp`，而 `reload()` 是在锁里替换它们，
  属于数据竞争（实际影响小，但 `go test -race` 会报）。
- `go test -race` 目前失败：`systun_test.go:87` 关闭文件与 `:111` 的 `sendFD` 并发。测试自身的问题，
  修完才能把 race 检查挂到 CI。
- `Routes.vue:101`：「全部批准」中途某台失败时只弹提示、不 `load()`，列表停在旧状态，
  用户会以为都没批。
- `weft.go:494`：`DeleteProfile` 用 `secretSet(key, "")` 而不是 `secretDelete`，钥匙串里留下空条目；
  随之删除的还有该服务端的 API Key 凭据，但没有吊销服务端那把 Key。
- `App.vue` 的 `onUnmounted` 里 `clearInterval(pollTimer)` 写了两遍。
- `helperVersion` 是手写常量（现在 0.2.2），改助手代码忘了 bump 会留下协议不匹配的旧助手，
  界面上只会看到「已安装但未就绪」。建议改成构建时注入的 hash 或时间戳。

## 确认没问题的部分

- SQLite 全部参数化，没有拼接 SQL；数据目录 0700，日志 0600。
- 凭证只进系统钥匙串，`SaveConfig` 会先把 `AuthKey` 清空再落库，`GetConfig` / `GetState` 不回传密钥。
- 管理 API 的路径参数一律 `PathEscape` / `QueryEscape`，没有 URL 拼接注入。
- 路由、地址全部先 `netip.ParsePrefix` / `ParseAddr` 再传 `exec.Command`（参数形式，没有 shell），
  服务端下发的内容无法变成命令。
- 前端没有 `v-html` / `innerHTML` / `eval`，矩阵页与 ACL 页都是模板渲染，没有 XSS 面。
- 同步码 16 位 × 32 字母表 ≈ 80 bit，`subtle.ConstantTimeCompare` 比对，监听只绑 100.x。
- `govulncheck ./...`：无已知漏洞；`npm audit --omit=dev`：0 条；`go vet`：干净；单元测试全过。

## 建议的处理顺序

1. 第 4 条的 `filepath.Base` + 校验和（改动小、收益直接）
2. 第 5 条的 CA 失败不降级（一行判断，避免「以为钉了其实没钉」）
3. 第 10 条、第 8 条第三点、第 9 条（都是小补丁）
4. 第 1 条应用内窗口的策略（需要先定产品口径）
5. 第 2、3 条提权链（要改安装布局，工作量最大）
